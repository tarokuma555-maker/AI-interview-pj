## 1. いまの状態(ひとことで)

医療・福祉職の転職希望者向けの、**AI面接官と声で練習するWebアプリ**。有料職業紹介事業の一部として無料で提供する。

- **開発ステップ2(音声会話の試作)は完了**。試作版は管理者向けの検証ツールとして `/poc` に残している。
- **製品版の先行版(求職者向けの画面)を本番に公開済み**。ログインとデータベース(開発ステップ3)の前の版で、招待リンクで入り、練習の記録は求職者のブラウザに保存する(設計書 14.2)。
- 次は「実機での確認」「Claude API をオーナーの契約に切り替え」「ログインとデータベース」の順(7 章)。

### 手元で動かす

```bash
npm install
cp .env.example .env.local      # 値を入れる。AI_PROVIDER=mock なら Claude の API キーなしで動く
npm run dev                     # http://localhost:3000/join#<POC_ACCESS_CODE の値>
```

- `/join#<コード>` が招待リンク。検証ツールは `/poc`(同じコードを画面で入力)。
- スマホでマイクを使うには HTTPS が必要なので、スマホでの確認は Vercel の URL で行う。

## 3. 作業の決まり

### 開発の進め方

- **Next.js 16 は学習データと違う**。コードを書く前に `node_modules/next/dist/docs/` の該当ページを読む(AGENTS.md)。
- push の前に、次をすべて通す。
  - `npm run lint`
  - `npm run typecheck`
  - `npm test`(Vitest。いま 164 件)
  - `npm run build`
- 画面を変えたら、`e2e/` の通しの確認も実行する(e2e/README.md)。
- 動きを変えたら、要件定義書・基本設計書の該当箇所と改訂履歴も更新する(版を1つ上げる)。
- コードのコメントには、根拠になる要件・設計の番号を書く(例:`要件 F-05-3`、`設計書 3.4`)。
- 面接官・評価のプロンプトの文面を変えたら、版の定数を上げる(`INTERVIEWER_PROMPT_VERSION` など)。
- コミットメッセージは英語で、1行目は命令形の要約、本文に理由を書く。モデル名は入れない。

### 画面と言葉

依頼者・利用者は日本語で、AI や技術に詳しくない。

- 依頼者への返事は日本語で、専門用語を避け、決めてほしいことをはっきり書く。
- 画面の言葉は、利用者の言葉で書く(要件 8.5 の UX-01〜08)。
  - 「音声認識」「API」「モデル」などの言葉や、エラーの番号は出さない(`features/app/messages.ts`)。
  - 1画面でやることは1つにする。
- 求職者の画面では、音声・AIの技術的な設定を選ばせない(要件 D-13)。設定を変えるのは管理者で、いまは環境変数で行う。

### 守ること

- API キーはヘッダーで送り、URL やログに出さない。
- 面接官の顔は実在の人物に似せない。
- 声を誰かに似せる場合は、本人の同意を得たものだけにする。
- 練習の内容を求人企業に渡す機能は作らない(要件 4.2)。

## 6. 依頼者・オーナーとのやりとりで決まっていること

- **関わる人**:依頼者(開発の担当)とオーナー(事業の持ち主)。依頼者が開発・運用を担い、オーナーは AI に詳しくない。
- **Claude API の切り替え**:オーナー向けの取得手順書を作成済み(Claude Docs の文書「Claude APIキーの取得手順(オーナー様向け)」。リンクは依頼者が持っている)。オーナーが開発担当を Console の組織に Developer として招待し、開発担当がキーを作って Vercel の `ANTHROPIC_API_KEY` を入れ替える段取り。
- **Google Cloud の API キー**:まだ依頼者のアカウントのもの。オーナーの契約にするかは未定。
- **応募先・応募書類のサンプル**:検証ツールのサンプルは看護師の転職(架空の病院)。依頼者の練習用に一時的に別の職種へ変えたことがあり、元に戻すよう言われて戻した。

## 8. 気をつけること・既知の課題

### 先行版の制約

- **招待コードは全員共通**
  - 環境変数 `POC_ACCESS_CODE` 1つを全員で使う。リンクが広まると誰でも使える。
  - 費用の歯止めは、Claude Console の月の上限と、サーバーの簡易なレート制限(インスタンスごとに数えるため目安)だけ。
- **記録は端末の中だけ**
  - 練習の記録はブラウザの localStorage に保存している。
  - 端末を替えたり、データを消したりすると失われる(画面と同意の文言でもそう説明している)。

### 試作版から引き継いだ作り

- **API の名前と保存の場所**:API のパスは `/api/poc/*` のまま。ブラウザへの保存のキーは `ai-mensetsu:*`。
- **英語の名前**:コード上の名前は試作版のまま。「面接官のスタイル」は `style`、回答方法は `answerBy`。

### 画面の小さな不足

- **応募先**:入力の途中で画面を離れると、入力した内容が消える。経歴の画面は、入力するたびに保存される。
- **結果**:評価の作成に失敗した記録は、記録の画面から作り直せない(面接直後の画面でだけ作り直せる)。

### 確認の範囲

- **プロンプトの検証**:Claude を使った本物の会話・評価は、AI 側の固定の文面(`AI_PROVIDER=mock`)と、依頼者の画面での試用でしか確かめていない。評価用のテストセット(要件 EV-04〜06)はまだない。
- **画面の検証**:声の確認や、Safari・Android の実機での動きは、自動の確認では見られない。
